## 运行环境

现有应用需要Python后端、持久化存储以及Whisper语音识别模型。只部署HTML页面不足以运行完整功能。可部署到支持Docker和持久化磁盘的云服务器或云平台；资源规格需按目标环境实测，语音识别主要消耗CPU和内存。

默认Docker配置包含Python依赖、转写脚本和预下载语音模型，程序运行时使用非root账户。云端入口读取平台PORT，并要求模型密钥、至少16字符访问码以及最终HTTPS地址。模型密钥留在服务器环境变量中。

## 云服务器部署

需要已有Linux云主机、Docker Compose以及已解析到主机的域名。开放80/443端口，用Caddy提供HTTPS；应用端口仅在容器网络内访问。

1. 在开发电脑执行 `python scripts/package_deploy.py`，得到 `output/AI-SDR-Agent-deploy.zip`，供本人上传服务器部署，不作为给老师的DEMO。
2. 在服务器解压，进入项目目录。复制 `deploy/.env.example` 为 `deploy/.env`，仅在服务器私密填写域名、模型接口密钥及访问码。
3. 执行 `docker compose --env-file deploy/.env -f deploy/compose.yaml up -d --build`。首次构建需要下载语音模型，必须检查构建成功。
4. 用 `docker compose --env-file deploy/.env -f deploy/compose.yaml ps` 检查状态，访问 `https://实际域名/healthz` 应返回ok。
5. 从手机蜂窝网络或另一台电脑打开链接，输入访问码，实际验证TXT/录音上传、转写、模型分析、人工与批量审核、导出，再把真实可访问的URL写入提交清单。

数据使用独立命名卷 `/data`；重启保留数据库和上传，语音模型位于镜像的 `/opt/asr-model`，不会被数据卷遮蔽。不要执行带 `-v` 的删除命令，以免删除演示数据。

## 使用托管平台

AutoDL 普通容器实例的本人测试配置见 [AUTODL.md](AUTODL.md)。它不支持实例内运行 Docker；自定义服务的账号资格及第三方分享限制需先确认，不能直接套用上面的 Docker 公网部署流程。

选择支持Docker的Web服务，使用项目Dockerfile；设置LLM_API_KEY、LLM_BASE_URL、LLM_MODEL、SDR_ACCESS_TOKEN、SDR_PUBLIC_ORIGIN，给 `/data` 挂载持久化磁盘。平台应提供HTTPS服务地址，SDR_PUBLIC_ORIGIN填该最终地址。健康检查路径为 `/healthz`。采用单实例，不能直接在多实例之间共享此SQLite实现。

部分免费套餐会休眠或清空临时磁盘。是否适合正式提交，应按平台当前规则和实测确认，不能仅凭第一次页面打开成功就验收。

## 数据与演示准备

部署包不包含本机runtime、已有客户线索、原始题目录音、完整真实转写或.env。验证报告只保留题目/合成案例，不能误作真实准确率。

默认线上数据库为空；提供题目/合成示例，并允许老师上传文件测试。若需把公司提供的真实录音预置到线上，应先确认上传到哪个平台及材料使用范围，再单独导入。云端录音是在服务器内转写，模型代理接收当前待分析文本。

## 临时外网演示

也可以将隔离的本地演示实例通过临时隧道提供外网链接。必须保留访问保护，不能直接公开本机已有业务数据；电脑、应用和隧道都需保持运行，地址和稳定性不适合默认当作长期交付。
