# 验收与效果评估

## 可重复程序测试

`python -m pytest -q --junitxml=docs/test-results.xml`

覆盖15字段契约、销售信号排除、原文引用归属、无依据补全、预算否定、意向门槛、拒绝优先、品牌/工商主体区分、地区行业约束、未知角色、错误不降级、审核记录与乐观锁、批量回滚、CSV公式防护、同源写入限制、可选访问令牌、录音索引和密钥不可从静态目录读取。

测试使用隔离数据库，不污染业务记录；回归测试通过数量记录在XML及最终评估报告。它证明指定不变量，不等于所有自然语言输入都准确。

## 模型案例验证

`python scripts/evaluate.py --mode llm`

输入：1条题目示例、3条合成案例，分别为高意向、礼貌收资料、人数及当前拒绝纠正、明确需求但计划未定。预期等级预先指定。保留实际JSON、引用、评分与模型名，不仅保存“通过”两个字。

此集合用于流程验证和提示调试，已经被开发过程查看，因此不能作为独立保留测试集报告业务准确率。

## 真实录音评估方案

题目提供38段录音。先完成机器转写，抽听和修正ASR，并标注销售/客户；再核验企业与意向。无法听清或无法唯一核验主体的样本标为“无法确定”，不编造唯一真值。

建议按企业分组形成开发集和保留集，避免相似通话泄漏；在保留集固定后才比较单次抽取、证据约束、消歧评分工作流。意向标注依据同一业务口径，对分歧案例讨论并保留原因。

| 指标 | 口径 |
| --- | --- |
| 企业名称抽取准确率 | 对可听清的原始称呼计算，明确品牌/主体层次 |
| 主体核验准确率 | 仅在有可靠主体金标的样本计算，同时报告样本数与自动覆盖率 |
| 错误补全率 | 错误地将品牌或简称补成具体主体的比例，单独展示 |
| 意向表现 | 混淆矩阵、各类Precision/Recall和Macro-F1；重点关注high误报 |
| 审核路由 | 错误进入审核的召回、审核工作量和修改后正确性 |
| 支持度校准 | 样本足够后比较分段支持度与实测正确率，当前不宣称概率校准 |

当前未完成真实主体与意向的独立人工标注，因此不发布真实业务准确率。机器转写数量是材料处理进度，不是识别准确率。

## 新增语义挑战与严格核对（2026-10-21）

`python scripts/audit_core.py`会实际调用模型，预期字段和行为位于`tests/fixtures/core_cases.json`。13条案例覆盖题目设计部人数、品牌错字、销售错误称呼、总员工与设计师区分、预算上限/未批、历史拒绝与重新推进、回电时间、当前/筹备门店、通话内指令及未知角色。结果保存于`core-evaluation.json`。它们是用于开发和回归的合成挑战，不是独立真实金标。

完整PDF逐项映射、干净环境验证与评分短板见 [严格核对报告](STRICT_AUDIT.md) 和 `audit-evidence.json`。GitHub仓库与最终视频仍须封版交付，不以测试通过替代这些交付项。

## 人工验收步骤

1. 打开工作台，确认无虚构初始统计。
2. 载入题目示例并分析：需求、杭州、设计师约15、预算和时间证据可见；企业仍提示品牌主体核验。
3. 载入礼貌收资料案例：销售的三万元与下周上线不抬高意向。
4. 载入人数纠正案例：5人而非15人；当前拒绝使最终等级为low。
5. 审核并修正字段，检查前后快照、版本递增与已通过导出。
6. 在两个页面提交相同旧版本，旧版本返回冲突。
7. 选两条批量订正并检查差异预览；版本冲突时无部分成功。
8. 选择真实录音，播放、读取本地转写、标注角色，再进行分析。
