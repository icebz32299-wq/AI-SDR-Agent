# SQL字段规则 v1.0

除数值型confidence_score和布尔型need_human_review外，其他字段均为字符串。未知字符串为空，不填“未知”或0。空字符串与明确的“0家”不同。

| 字段 | 规则 |
| --- | --- |
| company_name | 原始客户名称；精确品牌别名可标准化为品牌。只有有来源且地区、行业匹配的核验记录可自动映射工商主体，不凭模型记忆扩写 |
| industry | 客户经营行业；销售介绍的适用行业不能作为客户行业 |
| area | 客户经营地；不从品牌总部、手机号归属地补全 |
| contact_name | 客户自报姓名或销售已确认称呼；可保留“张总”，不扩写名字 |
| contact_title | 明确职位；“张总”不能自动转成总经理 |
| phone | 客户确认的号码，可保留138xxxx1234；不凭文件名认定客户联系方式 |
| intent_level | 仅high、medium、low；无证据时low为暂分类并明确说明不等于拒绝 |
| intent_reason | 原文事实与评分解释；人工改级须更新理由 |
| demand_summary | 客户明确需求，简短概括；不写入销售自行介绍的功能 |
| mendian | 保留约数、区间、当前门店数；未知为空 |
| shejishi | 只填写明确的设计师/设计团队人数；题目“设计部大概15个人”填写“约15人”并保留部门口径依据。不用全公司人数代替；已说明混合非设计岗位时仅填明确设计师人数，否则留空核实 |
| call_time | 明确通话元数据或用户输入，推荐ISO8601带时区；不以系统运行时间代替 |
| next_action | 与已确认信息一致；主体不明时补问，明确拒绝时尊重停止联系要求 |
| confidence_score | [0,1]启发式证据支持度，未校准为正确概率；人工不修改以免伪造机器结论 |
| need_human_review | 企业歧义、证据缺失、角色未确认、边界评分等任一触发即true；人工通过后false |

## 证据结构

内部Fact包含value、quote、turn_id；Signal包含strength、quote、turn_id、explanation。每段发言有稳定的T编号和speaker。程序验证quote存在于对应发言中；除联系人称呼外，销售发言不得作为事实或意向信号证据。

名称、职位和手机号须原文直接支持，禁止以一段真实引用掩盖凭空扩写的字段值。人数等可做有限语义归一化，但保留近似关系。引用存在不代表语义必然正确，复杂否定、纠正仍需模型理解和人工复核。

## 来源与时间

题目示例、合成测试、真实录音、手动输入分别标识。ASR默认speaker=unknown；人工逐段标注后才形成明确角色。录音文件名时间为元数据来源，录音号码仅脱敏显示，不自动认定为已核实联系人号码。
