# 题目要求与开发规划

## 原始目标

酷家乐XDR通话转写文本自动形成SQL（Sales Qualified Lead）线索；重点解决企业抬头和客户意向识别，并开发低置信度人工干预工具。

原始题目为项目同级的《AI应用开发实习生笔试题目.pdf》，共4页。核心权重：企业抬头30%、客户意向30%、工作流与代码20%、人工工具10%、文档与录屏10%。

## 验收映射

| 要求 | 实现与证据 |
| --- | --- |
| 输入电话沟通记录文本 | 文本输入、题目示例、真实录音转写文本 |
| 规定JSON结构 | `app/models.py`的SQLLead，严格15字段；API、下载与导出一致 |
| 企业抬头还原 | 原始称呼、别名与近似候选、自报全称、上下文约束的人工核验映射；外部搜索可选 |
| 意向high/medium/low与理由 | 客户信号＋版本化五维评分卡＋高意向门槛＋明确拒绝优先 |
| 人工干预 | 原文对照、字段修正、理由、审核记录、批量订正、反馈词库 |
| 运行与异常处理 | 明确模型错误、有限重试、结构及证据校验、事务、重复提交保护 |
| DEMO链接 | 完整原文允许二选一：可访问的在线Demo，或GitHub仓库＋运行说明。本项目选择仓库方案，待发布并验证干净环境复现 |
| 设计文档 | 架构、工作流、Prompt、企业方案、评分与人工工具均有说明 |
| 录屏5—10分钟 | 演示脚本及最终演示文件，素材来源明确 |
| 邮件提交内容 | 设计文档 + DEMO交付链接（本项目选GitHub仓库＋运行说明）+ 录屏文件 |

## 规划与取舍

1. 定义字段、未知值和证据边界。
2. 验证用户提供的模型代理接口，记录实际返回模型名。
3. 完成工作流核心逻辑与事务测试。
4. 完成简洁、美观、响应式的分析与审核页面。
5. 接入真实录音、本地转写和人工角色标注。
6. 用题目与边界案例运行真实模型验证，保留结果与局限。
7. 准备可分享的GitHub仓库，在干净环境按README复现，交付设计文档、仓库链接及录屏文件。公网部署为可选项，不是本次必做项。

优先投入两个60%权重的识别难点。不会通过多Agent数量、复杂基础设施或装饰性大屏替代业务准确性。语音转写是输入适配层，不改变题目以文本分析为核心的要求。
