# 录音转写与模型失败排查记录（2026-10-20）

## 已确认的现场情况

1. 数据库有一条上传录音转写失败记录，错误为大量重复识别。失败上传与后来的成功上传内容SHA-256一致，说明该文件并非始终无法上传或解码。既有禁止跨片段累积提示的设置保留，本轮补充了质量触发的自动恢复。
2. 服务访问日志有一次转写完成后的模型分析HTTP 502，随后重新分析成功。历史代码未记录细分原因，无法事后证明那一次是超时、限流还是结构错误。本轮补齐不含正文和密钥的诊断记录。
3. 现场模型真实返回的用量包含reasoning_tokens，说明思考也消耗输出额度；旧实现固定6000输出额度，遇到length直接失败，没有扩容恢复。此项是已验证的失败路径，不等于断言它就是历史502的具体原因。
4. 部分材料时长约360～520秒，但默认VAD检测到的人声只有几秒或几十秒，旧缓存只有极少文本。VAD可能漏检，文件也可能包含长静音/非语音，均需回听；不能用文件总时长推断实际谈话长度。
5. Windows隐藏运行的热重载进程发出Reloading后，实际仍由旧子进程提供接口；新质量元数据未出现。已确认无进行中转写任务后，以稳定模式重启正式服务，接口确认新版代码生效。run.bat默认移除热重载，避免编辑代码中断长任务。

## 实现修复

- 录音：完整解码后转写，低音量适度放大，反相双声道避免平均下混相消；重复、有效语音过少或空识别时调整VAD重试一次，选择较可靠结果，不保存不完整/大量重复/空识别为成功。
- 质量：结合识别时间片段覆盖与VAD有效语音时长提示，不将跨越静音的长时间戳误当成整段人声。
- 模型：总请求最多3次；临时限流、服务错误及网络超时有限重试；输出截断时从原始输入重新生成并增加额度；JSON模式不兼容时仍保留本地严格结构校验；null未知值和整数型字符串等安全格式差异规范化；真正结构错误最多修复一次。
- 页面：完成任务直接使用带质量信息的返回全文，减少完成后额外请求断连导致的误报；失败保留录音及原有文本，显示具体阶段和可执行的错误提示。
- 诊断：runtime/diagnostics.jsonl只记录阶段、错误码、次数、状态、耗时等，不记录密钥、通话正文、上游原始内容和思考内容。

- 新Prompt版本为1.1，运行记录可区分旧版；旧审核及分析记录的版本不改写。
